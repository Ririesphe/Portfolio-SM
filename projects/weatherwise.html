WeatherWise Web Application

A responsive weather application for areas around Cape Town that turns live data from the OpenWeatherMap API into clear, plain-language updates.

Live demo (opens in a new tab) View code on GitHub (opens in a new tab)

The problem

General weather apps return a lot of data, and searching by place name can return the wrong location. People in and around Cape Town need a quick, reliable way to check conditions for their own area, explained in words rather than raw numbers.

My role

I designed and built WeatherWise, including the interface, the API integration and the supporting pages, and published it on Netlify.

How it works

A user enters an area, and WeatherWise requests current conditions and the forecast for that location from the OpenWeatherMap API.

  • Supports ten areas: Cape Town, Green Point, Blouberg, Table View, Claremont, Rylands, Woodstock, Constantia, Hout Bay and Stellenbosch.
  • Shows the current temperature and conditions with a plain-language description that adapts to the weather and time of day, such as "Expect sunny skies this afternoon."
  • Shows a three-day forecast built from the API's forecast data.
  • Flags severe conditions in an alert card, or confirms there are no severe weather alerts.
  • Includes About and Contact pages, sign-up for weather alerts, and a login, registration and logout flow.

Technical decisions

Fixed area coordinates
Instead of searching by free-text place name, each supported area maps to known latitude and longitude, so results always match the right part of Cape Town.
Two API endpoints
Current conditions and the forecast come from separate OpenWeatherMap endpoints, requested with async/await and metric units.
Readable summaries
Weather conditions map to short written descriptions and icons, so the main message is understandable at a glance.
Error handling
Unsupported areas and API errors show a message instead of breaking the page.
Client-side accounts
Login and registration use the browser's local storage, keeping the project fully static for hosting.

Next steps

To take WeatherWise further, sign-in would move to a proper authentication service instead of browser storage, and API requests would go through a small server so the API key isn't exposed in the browser.
