Smarties Ticket System

An IT support and issue-tracking platform that uses AI to classify tickets and route them to the right department, with dashboards, notifications and reporting for administrators.

Live demo (opens in a new tab) View code on GitHub (opens in a new tab)

The problem

Support requests usually arrive as unstructured messages. Someone has to read each one, decide which department owns it, judge how urgent it is and pass it on. Done by hand, this is slow and inconsistent, and sensitive requests can end up with the wrong people.

Smarties automates that first step, so every ticket is classified and routed as soon as it is submitted, with administrators keeping oversight of anything sensitive.

My role

I developed the application across the stack: the Flask back end and routing logic, the AI integration, the Firestore data layer, the page templates, and reporting and exports.

How it works

When a user submits a ticket, the system analyses it, routes it and keeps everyone informed.

  • AI analysis: the ticket text goes to a language model through the OpenRouter API, which returns the department (IT, Finance, HR or Operations), the tone (Urgent, Friendly or Formal), a risk level and a bias flag.
  • Automated routing: keyword rules set the department and priority, and the ticket is assigned to a team member in that department.
  • Approval workflow: Finance and HR tickets, urgent tickets and anything flagged as high risk or potentially biased need administrator approval.
  • Notifications: administrators, assignees and requesters receive in-app notifications, and requesters get an email confirmation.
  • Ticket chat: each ticket has a discussion thread with file attachments.
  • Administration: dashboards, an audit log that can restore deleted tickets, business reports with charts, CSV and PDF exports, and a governance report.
  • Accounts: registration, login, role-based access for users and administrators, and password reset by email.

Development process

The system was built in stages. The automated routing engine was added as a later feature on top of ticket submission and classification, and the data layer moved from an earlier SQLite database to Firebase Firestore, with a migration route to carry existing data across.

Technical decisions

AI with a fallback
If the AI service is unavailable or returns an unexpected answer, the system falls back to keyword-based classification and tone detection, so tickets are always processed.
Human approval for sensitive tickets
Automation handles routine routing, while sensitive, urgent or flagged tickets wait for an administrator before work starts.
Flask and Jinja
A lightweight Python framework with server-rendered templates keeps the application straightforward to build and deploy.
Firebase Firestore
A managed cloud database replaced the original local SQLite file, which suits serverless hosting on Vercel.
Role-based access
A login decorator and role checks protect every route, so administrator pages such as audit logs and compliance reports are only available to administrators.
Generated reports
Chart.js draws report charts in the browser, and ReportLab generates downloadable PDF reports on the server.
